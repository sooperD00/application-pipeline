- [ ] git commit -m "test-vehicles: gate the run behind two human checkpoints

Running the lab meant trusting whatever was in samples/ and finding out
afterward. Two stops, each answering a different question.

Phase 1 — 'did I grab the wrong files'
  Inventory from stat() alone, sorted by bytes descending. No file is
  opened for content, so a stray 50 GB costs microseconds to notice
  rather than however long it takes to parse. Anomalies sort to the
  ends: biggest at top, empty at bottom. Mislabeled files are called
  out here too — 8 magic bytes, not a load.

Phase 2 — 'will it truncate, what will it cost'
  Runs after extraction, which is local and free, so bailing here has
  still spent nothing. Sorted by estimated tokens, with a cache column
  — on a re-run most files cost nothing and that changes the decision.
  Loader warnings collect into one block instead of scrolling past
  while calls are already firing.

Truncation flag is not an arbitrary length. Buckets carry a verbatim
source_quote, so output length tracks input length; a long CV can blow
--max-tokens and truncate, which makes its coverage number meaningless.
Flagged before the spend instead of warned about after.

Also: the API-key check moved above phase 1, so a missing key fails in
half a second instead of after you've read a file list.

--yes skips both checkpoints. --dry-run skips them too — a prompt that
fires when there's nothing at stake is friction you'd route around."
